## 採用判断

- 同梱の採用基準: depression 全件で Recall ≥ 0.90（閾値 0.5）。既定モデルの置き換え基準: Recall ≥ 0.95。
- 失敗（API のエラーでフォールバックになった件）が全体の 1% を超えた実行は無効として扱う。
- A-H1 (claude-haiku-5-5): Recall 95.7%（TP 268 / 陽性 280）。同梱の採用基準 **満たす**、既定モデルの置き換え基準 満たす。 CQ1〜5 は smoke で外挿した費用を本人に示してから実行する。

## 評価の限界

- 評価は開発者自身によるもので、第三者による独立した検証はない。
- depression は前臨床の系統的レビュー（うつ病の動物モデル）で、抄録はほぼ英語。他の分野・言語での性能は確かめていない。
- depression は条件の調整にも使ったデータセットで、値は楽観的になりえる（この実験では Anthropic の条件を調整していないが、プロンプトと判定基準の文は他のモデルの調整後のものを使っている）。
- 評価データは公開済みの系統的レビューなので、LLM が学習の段階で見ている可能性があり（データの汚染）、性能が高めに出ることがある。
- モデルの提供元が更新すると性能は変わりえる。モデル ID は固定だが、提供終了や挙動の更新はこの結果に反映されない。
- 打ち切りで使用量が返らなかった件は費用に入らず、費用は実際の請求よりわずかに少ない。

## 所見と決定（2026-11-12、手で書き足した節。summarize.ts を流し直したら書き戻す）

- 実行日 2026-11-12。認証は `ant` CLI v2.9.0 の OAuth（`plan.md`「実装」）。リクエストの本文はアプリと同じ。
- 各全件の実行の件数は元データと一致した（depression 1,993・cq1 5,628・cq2 3,400・cq3 1,038・cq4 4,326・cq5 2,253、ref_id の重複なし）。
- A-H1（Haiku）: 同梱の採用基準と既定モデルの置き換え基準を満たす。ただし Specificity 65.3%・Precision 31.1% は B4（86.3%・53.4%）より低く、人の確認に回る件が多い。拒否（stop_reason=refusal）が3件で、指標には数えていない（失敗の率 0.15%、無効の閾値 1% の内）。本人の了承（同日のカード）で CQ1〜5 も全件実行した。合算 Recall 90.0%（233/259）。cq1 は 79.6% で flash-lite GA（83.2%）を下回る。
- A-S1（Sonnet）: Recall 87.5% で同梱の採用基準を満たさない。除外寄りで、Specificity 92.5%・Precision 65.5% は B4 より高い。閾値のスイープでは 0.30 で Recall 92.9%、0.10 で 95.4%（`threshold_sweep.md`）。アプリの閾値は 0.5 固定なので、採用の判定は 0.5 の値で行った。
- 本人の決定（同日のカード）: 基準を満たさなかった Sonnet は**注記を付けて同梱を続ける**。README の同梱モデルの一覧に「同梱の採用基準 Recall ≥ 0.90 を満たさない」と書いた。`docs/help.html` にはモデルごとの説明が無いため変えていない。アプリのモデルの説明（`src/_locales/*/messages.json` の「ベンチマーク未実施」）は `src/` の変更なので別の PR で直す。
- CQ1〜5 の閾値のスイープは今回の範囲外（`threshold_sweep.md` は depression のみ）。
