# コマンドラインからプロジェクトを作る（`scripts/create-project.mjs`）

プロジェクトの新規作成（スプレッドシート作成 → RIS 取り込み → 招待）を、拡張機能の画面を開かずにコマンド1回で行うためのスクリプトです（Issue #245）。画面を自動操作するのではなく、拡張機能と同じ `src/lib` の関数から Google Sheets / Drive の API を呼びます。

この文書は、**このコマンドを自分の環境で使えるようにしたい人と、その人を手伝う AI アシスタント**に向けて書いています。AI アシスタントは、末尾の「AI アシスタントが手伝うときの手順」を先に読んでください。

## 誰が使えるか

このコマンドは、OAuth クライアント（デスクトップ アプリ型）のIDとシークレットを環境変数から読みます。**クライアントは配布していません。使う人が自分の Google Cloud プロジェクトに1つ作ります**（初回のみ、10分ほど）。

自分の Google Cloud プロジェクトで作ったクライアントは、Chrome ウェブストアで配布している拡張機能とは別のアプリとして扱われます。そのため、**このコマンドで作ったプロジェクトを拡張機能で初めて開くときは、作成者自身も「Googleで許可する」からそのシートを1回選ぶ必要があります**（招待された判定者が初回に行う操作と同じです）。データはあなたの Google ドライブに作られ、他の誰のサーバーも経由しません。

## 必要なもの

- Node.js 22 系と npm（`node --version` で確認）
- このリポジトリの clone と `npm ci`
- Google アカウント
- 取り込む RIS / nbib ファイル

## 初回の準備: OAuth クライアントを作る

ブラウザで [Google Cloud Console](https://console.cloud.google.com/) を開いて行います。画面の名称は Google 側の変更で変わることがあります。見つからないときは、コンソール上部の検索欄に項目名を入れて探してください。

1. **プロジェクトを選ぶ（無ければ作る）。** 画面上部のプロジェクト選択から「新しいプロジェクト」。名前は何でも構いません。
2. **API を2つ有効にする。** 「API とサービス」→「ライブラリ」で **Google Sheets API** と **Google Drive API** を検索し、それぞれ「有効にする」。
3. **同意画面を設定する。** 「API とサービス」→「OAuth 同意画面」（「Google Auth Platform」と表示されることがあります）。
   - 対象（ユーザーの種類）: 個人の Google アカウントなら「外部」。Google Workspace の組織内だけで使うなら「内部」。
   - アプリ名・サポートメール・連絡先メールを入力します。
   - 「外部」で公開ステータスが「テスト中」のときは、**「テストユーザー」に自分のメールアドレスを追加**します。追加していないアカウントではログインできません。
4. **クライアントを作る。** 「API とサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」。
   - アプリケーションの種類: **デスクトップ アプリ**
   - 名前は何でも構いません（例: `tiab-cli`）。
   - リダイレクト URI の登録は不要です（このコマンドは自分のパソコンの `127.0.0.1` で認可結果を受け取ります）。
5. 表示された **クライアント ID** と **クライアント シークレット** を控えます。

このコマンドが求める権限は次の2つだけです。

- `userinfo.email`: ログインしたアカウントのメールアドレスを表示するため
- `drive.file`: このコマンドが作ったファイルだけを読み書きするため（あなたのドライブの他のファイルには触れません）

### 「テスト中」のままだと、ログインが定期的に切れます

公開ステータスが「テスト中」のアプリでは、保存されたログイン情報が短い期間（Google の説明では7日）で無効になります。切れたらコマンドが再ログインを求めるので、もう一度ブラウザで許可すれば続けられます。切れないようにするには、同意画面の公開ステータスを「本番環境」に変えます。

## 環境変数を設定する

リポジトリ直下の `.env`（`.gitignore` 済み。無ければ `.env.example` をコピーして作る）に次の2行を足します。

```
CLI_OAUTH_CLIENT_ID=<クライアント ID>
CLI_OAUTH_CLIENT_SECRET=<クライアント シークレット>
```

シェルの環境変数として設定しても構いません（同じ名前の環境変数が既にあれば、`.env` よりそちらが優先されます）。

**`.env` をコミットしないでください。** シークレットをチャットや issue に貼らないでください。

## 使い方

まず `--dry-run` で、ファイルがどう解釈されるかを確かめます。この段階では Google に接続せず、環境変数も要りません。

```bash
node scripts/create-project.mjs --title "プロジェクト名" --ris path/to/records.ris --dry-run
```

解釈できた件数、重複で除外される件数、要確認の重複候補の組数、抄録が 15,000 字で切り詰められる件数が出ます。

問題なければ `--dry-run` を外して実行します。

```bash
node scripts/create-project.mjs --title "プロジェクト名" --ris path/to/records.ris
```

- 初回はブラウザが開き、Google の許可画面が出ます。開かないときは、ターミナルに表示された URL を自分でブラウザに貼ってください。「このアプリは Google で確認されていません」と出た場合は、自分で作ったクライアントであることを確かめたうえで「詳細」から続行します。
- 終わると、スプレッドシートの ID と URL、取り込んだ件数、招待した相手が1行ずつ出ます。

判定者を招待するときは `--share` を付けます。**指定した相手に Google から招待メールが届きます。** 付けなければ、作成と取り込みで止まります。

```bash
node scripts/create-project.mjs --title "プロジェクト名" --ris path/to/records.ris --share a@example.com,b@example.com
```

| オプション | 意味 |
| --- | --- |
| `--title <文字列>` | プロジェクト名（スプレッドシート名とフォルダ名になる）。必須 |
| `--ris <パス>` | 取り込むファイル（`.ris` / `.nbib` / `.txt`）。必須 |
| `--share <メール,メール>` | 編集者として招待する相手。カンマ区切り |
| `--dry-run` | ファイルの解釈結果だけを出し、Google には接続しない |
| `--lang ja\|en` | 招待メールに載せる案内文の言語（既定 `ja`） |
| `--help` | 使い方を表示 |

`npm run create-project -- --title ... --ris ...` でも同じです。

## 作られるもの

- Google ドライブの `tiab-reviewer-plugin/<プロジェクト名>/` フォルダと、その中のスプレッドシート（`References`・`Decisions`・`Config` タブ）
- 拡張機能の画面から作ったプロジェクトと同じ構造です。取り込み時の重複の扱い（PMID・DOI の一致は除外、タイトルだけの一致は取り込んだうえで「重複候補」として記録）も同じです。

## 拡張機能で開く

出力された URL を、拡張機能のプロジェクト接続欄に貼って開きます。「このシートを使うには、Googleの画面で一度だけこのシートを選ぶ必要があります」と表示されたら、「Googleで許可する」を押してそのシートを選んでください。

## ログイン情報の保存場所

リフレッシュトークンを `~/.tiab-review-plugin/cli-credentials.json`（リポジトリの外、ホームディレクトリの下）に保存します。場所を変えたいときは環境変数 `TIAB_CLI_CREDENTIALS_PATH` にファイルのパスを指定します。

- 別のアカウントでやり直す・ログアウトする: このファイルを削除します。
- このファイルを他人に渡さないでください。あなたの代わりに、このコマンドが作ったファイルを読み書きできます。

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| `CLI_OAUTH_CLIENT_ID` が無いと言われる | `.env` に2行が入っているか、リポジトリ直下で実行しているかを確認 |
| ブラウザで「アクセスをブロック: … は Google の審査プロセスを完了していません」 | 同意画面が「テスト中」で、ログインしたアカウントがテストユーザーに入っていない。追加する |
| ブラウザで `redirect_uri_mismatch` | クライアントの種類が「デスクトップ アプリ」になっていない。作り直す |
| しばらく使えていたのに再ログインを求められる | 「テスト中」のアプリのログイン情報は短期間で切れる。もう一度許可する |
| `error: 取り込みの途中で失敗しました` | **そのまま再実行しない。** 表示されたスプレッドシートを開き、`References` タブに何件入っているかを確認する。途中まで入ったシートは Google ドライブのゴミ箱へ移し、時間をおいて最初からやり直すのが確実 |
| 招待に失敗した相手がいる | スプレッドシートは作成済み。拡張機能の共有画面か Google ドライブから、その相手を個別に追加する |
| フォルダを共有できなかったという警告 | スプレッドシートは共有済み。フォルダは Google ドライブで手動共有する |

## AI アシスタントが手伝うときの手順

利用者がこのコマンドを使えるようにする作業を頼まれたときの進め方です。

**利用者本人にしかできないこと**（代わりにやろうとしない。手順を示して待つ）

- Google Cloud Console での操作（プロジェクト作成、API の有効化、同意画面、クライアント作成）
- クライアント ID とシークレットを `.env` に書き込むこと
- ブラウザに出る Google の許可画面での操作

**あなたができること**

1. `node --version` が 22 系であること、`node_modules` があること（無ければ `npm ci`）を確かめる。
2. `.env` があるか、`CLI_OAUTH_CLIENT_ID` と `CLI_OAUTH_CLIENT_SECRET` の**行があるか**を確かめる。値は表示しない（`grep -c` などで有無だけを見る）。
3. 無ければ、上の「初回の準備」を順に案内する。利用者が今どの画面にいるかを聞き、1手順ずつ進める。
4. 利用者の RIS ファイルで `--dry-run` を実行し、件数を利用者に見せる。切り詰められる抄録や重複候補が多いときは、その意味を説明する。
5. 利用者が件数を確認してから、`--dry-run` を外して実行する。ブラウザの許可画面は利用者が操作する。
6. 出力の `spreadsheet_id` と `url` を利用者に伝え、拡張機能での開き方（上の「拡張機能で開く」）を案内する。

**してはいけないこと**

- クライアント シークレット、`.env` の中身、`cli-credentials.json` の中身、アクセストークンを、表示・要約・ログ出力・他のサービスへ送信しない。
- 利用者が招待する相手を明示していないのに `--share` を付けない。付けると相手に招待メールが届き、取り消せない。
- `error: 取り込みの途中で失敗しました` の後に、同じコマンドを自動で再実行しない。文献が二重に入ることがある。状況を利用者に伝え、シートの確認を頼む。
- 動作確認のために、`--dry-run` なしの実行を繰り返さない。実行のたびに利用者のドライブへ新しいプロジェクトができる。
- スコープを増やす、クライアントの種類を変える、といった認証まわりの改造を勧めない（理由は [src/platform/AGENTS.md](../../src/platform/AGENTS.md)）。
